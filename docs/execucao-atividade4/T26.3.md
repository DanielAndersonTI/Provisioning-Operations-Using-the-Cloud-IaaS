# T26.3 — Serviços, healthchecks e logs no volume

| Campo | Valor |
| --- | --- |
| Data | 09/11/2026, 23:05 (local); evidências em UTC |
| Fase | Fase 26 |
| Status | concluída |
| Evidências | `T26.3-ps`, `T26.3-health`, `T26.3-ports`, `T26.3-volume-logs`, `T26.3-restart-policy` |

## Objetivo

Comprovar que os três containers estão em execução, com healthcheck saudável, portas publicadas, política de reinício e logs sendo gravados no volume.

## Comandos

```bash
sudo docker compose --env-file /etc/poi-atividade4/docker.env ps
sudo docker inspect --format '{{.State.Health.Status}}' <container>
sudo ss -ltnp | grep -E ':800[012]'
sudo ls -l /mnt/atividade3-logs/{cpu,memory,io}
sudo docker inspect --format '{{.HostConfig.RestartPolicy.Name}}' <container>
```

## O que aconteceu

Os três containers ficaram `Up (healthy)`. As portas 8000/8001/8002 são atendidas por `docker-proxy`, em IPv4 e IPv6. Os logs vão para o volume, em arquivos pertencentes a `10001:10001`, com as linhas de startup de cada aplicação. A política de reinício é `unless-stopped` e o driver de log é `json-file` com `max-size: 10m` e `max-file: 5`.

## Saída

```text
poi-atividade4-cpu-1     Up 24 seconds (healthy)   0.0.0.0:8000->8000/tcp
poi-atividade4-memory-1  Up 24 seconds (healthy)   0.0.0.0:8001->8000/tcp
poi-atividade4-io-1      Up 24 seconds (healthy)   0.0.0.0:8002->8000/tcp

poi-atividade4-cpu-1     healthy
poi-atividade4-memory-1  healthy
poi-atividade4-io-1      healthy

LISTEN 0 4096 0.0.0.0:8000 ... users:(("docker-proxy",pid=1027848,fd=7))
LISTEN 0 4096 0.0.0.0:8001 ... users:(("docker-proxy",pid=1027880,fd=7))
LISTEN 0 4096 0.0.0.0:8002 ... users:(("docker-proxy",pid=1027829,fd=7))

poi-atividade4-cpu-1     unless-stopped / log json-file map[max-file:5 max-size:10m]
poi-atividade4-memory-1  unless-stopped / log json-file map[max-file:5 max-size:10m]
poi-atividade4-io-1      unless-stopped / log json-file map[max-file:5 max-size:10m]
```

## Decisões

Manter o log da aplicação no volume (e não só no `docker logs`) preserva a continuidade com a Atividade 3: o `logrotate` já instalado continua rotacionando `app.log`. O driver `json-file` fica limitado para que o `docker logs` não cresça sem limite.

## Problemas

As linhas `ConnectionResetError` que aparecem no início do `app.log` são do encerramento das instâncias antigas sob o `systemd`, não dos containers.
