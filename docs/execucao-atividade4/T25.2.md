## Objetivo

Construir `poi-cpu`, `poi-memory` e `poi-io` a partir do mesmo Dockerfile, variando apenas o argumento `PROFILE`.

## Comandos

```bash
cd ~/atividade3
sg docker -c 'docker build --build-arg PROFILE=cpu    -f apps/Dockerfile -t danielandersonss/poi-cpu:1.0.0    .'
sg docker -c 'docker build --build-arg PROFILE=memory -f apps/Dockerfile -t danielandersonss/poi-memory:1.0.0 .'
sg docker -c 'docker build --build-arg PROFILE=io     -f apps/Dockerfile -t danielandersonss/poi-io:1.0.0     .'
```

## O que aconteceu

As três imagens foram construídas sobre `python:3.12-slim`, todas com 114 MB. O contexto enviado ao builder foi de 15,32 kB — o `.dockerignore` cumpriu o papel de deixar evidências, resultados e automação de fora. As camadas base (`WORKDIR`, usuário, cópia do módulo) vieram de cache entre as três construções; só a cópia do entrypoint do perfil difere, e por isso o ID das imagens é diferente.

O `docker images` arredonda para 120MB; o tamanho exato medido depois é 114 MB.

## Decisões

Reaproveitar o cache das camadas comuns acelera a segunda e a terceira construções sem sacrificar a separação por perfil. A imagem roda como `appsvc` (UID/GID 10001), o que já prepara a escrita no volume da VM, cujo dono será ajustado para o mesmo UID.
