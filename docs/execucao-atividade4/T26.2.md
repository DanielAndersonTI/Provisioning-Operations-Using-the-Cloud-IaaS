## Objetivo

Baixar as imagens publicadas, parar e desabilitar as units `systemd` que ocupam as portas 8000-8002 e subir os três containers com Docker Compose, sem build na VM.

## Comandos

```bash
sudo systemctl is-enabled app-cpu app-memory app-io
sudo docker compose --env-file /etc/poi-atividade4/docker.env pull
sudo systemctl stop app-cpu app-memory app-io
sudo systemctl disable app-cpu app-memory app-io
sudo docker compose --env-file /etc/poi-atividade4/docker.env up -d --no-build
```

## O que aconteceu

Antes do cutover as três units estavam `enabled`/`active` e as portas 8000-8002 eram atendidas por `python3`. O pull baixou as três imagens (44 MB comprimidas cada) em 20 s. As units foram paradas e desabilitadas, as portas ficaram livres, e o `up -d --no-build` criou a rede `poi-atividade4_default` e subiu os três containers, ainda com `health: starting`.

## Decisões

A ordem é deliberada: **pull → stop → chown → up**. O pull antes da parada faz a fase abortar com as aplicações no ar se a imagem não existir ou a rede falhar. Se o `up` falhar, a fase executa `compose down` e `systemctl enable --now app-cpu app-memory app-io` (rollback automático); não foi necessário acionar. As units foram desabilitadas, não removidas, para permitir o retorno à Atividade 3.
