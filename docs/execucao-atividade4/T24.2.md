## Objetivo

Deixar a VM da Atividade 3 com Docker Engine e o plugin Compose v2, sem remover nem alterar o volume de logs já montado. A instalação tenta primeiro os pacotes da distribuição, depois o repositório oficial da Docker e, por último, o binário standalone do Compose; a evidência registra qual caminho funcionou.

## Comandos

```bash
cat ~/atividade3/payload4/install-docker.sh | ssh ... ubuntu@150.165.85.77 'sudo bash -s'
sudo docker version
sudo docker compose version
df -h /mnt/atividade3-logs
```

## O que aconteceu

A instalação foi feita com os pacotes da distribuição (primeiro caminho previsto): `docker.io` `29.1.3` e `docker-compose-v2` `2.40.3`. O driver é `overlayfs`, com root em `/var/lib/docker` sobre uma partição de 19 GB (16 GB livres). O volume `/dev/vdb` (974 MB, ext4) continuou montado em `/mnt/atividade3-logs`, e as três units `systemd` da Atividade 3 seguiam `active`.

## Saída

```text
== tentativa 1: docker.io da distribuição
== tentativa 1: docker-compose-v2 da distribuição
== usuário ubuntu adicionado ao grupo docker
== Docker e Compose prontos

cliente 29.1.3 / servidor 29.1.3
Docker Compose version 2.40.3+ds1-0ubuntu1~24.04.1
driver=overlayfs root=/var/lib/docker

/dev/vda1        19G  2.6G   16G  14% /
/dev/vdb        974M  1.3M  946M   1% /mnt/atividade3-logs
```

## Decisões

Não foi necessário recorrer ao repositório oficial da Docker nem ao binário standalone do Compose: o pacote da distribuição em Ubuntu 24.04 já traz o plugin v2, o que mantém a VM sem repositório externo adicional.

## Problemas

Nenhum. A linha `usuário ubuntu adicionado ao grupo docker` aparece duas vezes porque o script considera `SUDO_USER` e `ubuntu`; é inofensivo e idempotente.
