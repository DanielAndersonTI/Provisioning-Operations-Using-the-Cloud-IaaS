# T6.2 — Formatação e primeira montagem

**Data (UTC):** 2026-10-29T03:28:22Z
**Fase:** 6 — volume de 1 GB para logs
**Status:** concluída
**Evidências:** `evidencias/T6.2-block-devices.txt` · `T6.2-block-devices.png` · `T6.2-mkfs.*` · `T6.2-mount.*`

## Objetivo

Dar sistema de arquivos ao disco novo e montá-lo em `/mnt/atividade3-logs`,
confirmando que dá para escrever e ler.

## Comandos executados

```bash
ssh ... 'lsblk -o NAME,SIZE,TYPE,FSTYPE,LABEL,MOUNTPOINT; sudo blkid /dev/vdb'
ssh ... 'if sudo blkid -s TYPE -o value /dev/vdb; then ...; else sudo mkfs.ext4 -L a3logs -m 1 /dev/vdb; fi'
ssh ... 'sudo install -d -m 0755 /mnt/atividade3-logs
    sudo mount LABEL=a3logs /mnt/atividade3-logs
    findmnt /mnt/atividade3-logs; df -h /mnt/atividade3-logs
    sudo sh -c "echo volume-ok > /mnt/atividade3-logs/teste.txt"'
```

## O que aconteceu

O `lsblk` mostrou o disco novo inteiro, sem partição e sem sistema de arquivos:

```text
NAME     SIZE TYPE FSTYPE LABEL           MOUNTPOINT
vda       20G disk
├─vda1    19G part ext4   cloudimg-rootfs /
├─vda14    4M part
├─vda15  106M part vfat   UEFI            /boot/efi
└─vda16  913M part ext4   BOOT            /boot
vdb        1G disk
```

Uso o disco **sem tabela de partição**: um volume de 1 GB montado direto como
`/dev/vdb` é o caso normal no Cinder, e criar uma partição só adicionaria uma
camada sem função.

O `mkfs.ext4 -L a3logs -m 1` criou o `ext4` com rótulo `a3logs` e reservou 1% em
vez dos 5% padrão. Em 1 GB, 5% seriam 50 MB presos — espaço que faria falta num
disco pequeno e que não serve para nada aqui, já que o volume não é do root.

A formatação é **condicional**: o comando só roda se `blkid -s TYPE` não achar
sistema de arquivos. Sem essa guarda, uma segunda execução do script apagaria os
logs que estivessem no volume.

A montagem foi feita por rótulo (`LABEL=a3logs`) nesta fase, e por UUID na fase
seguinte, dentro do `/etc/fstab` — UUID é mais seguro porque o rótulo pode ser
repetido.

| Verificação | Resultado |
| --- | --- |
| Sistema de arquivos | `ext4`, UUID `1de1bd6e-b421-49ca-abeb-976698e2abd1` |
| Ponto de montagem | `/mnt/atividade3-logs` |
| Espaço | 974 MB disponíveis (1 GB nominal) |
| Escrita | `volume-ok` lido de volta |

## Saída

```text
TARGET               SOURCE   FSTYPE OPTIONS
/mnt/atividade3-logs /dev/vdb ext4   rw,relatime

Filesystem      Size  Used Avail Use% Mounted on
/dev/vdb        974M   24K  948M   1% /mnt/atividade3-logs

volume-ok
```

## Decisões

- `ext4` com rótulo `a3logs`, sem partição.
- `-m 1` para não desperdiçar 50 MB em um volume de 1 GB.
- `mkfs` protegido por `blkid`, para o script poder ser repetido sem apagar dados.

## Problemas e pendências

O tamanho de 974 MB em vez de 1024 MB é o overhead do próprio `ext4` (metadados
e journal) — não é erro de criação nem volume truncado.
