# T0.2 — Conectividade com a nuvem

**Data (UTC):** 2026-10-29T02:26:03Z
**Status:** concluída
**Evidências:** `evidencias/T0.2-connectivity.txt`

## Objetivo

Confirmar que a VDI alcança os endpoints da nuvem antes de tentar autenticar.

## Comandos executados

```bash
getent hosts cloud.lsd.ufcg.edu.br
curl -o /dev/null -w '%{http_code}' https://cloud.lsd.ufcg.edu.br/
curl -o /dev/null -w '%{http_code}' https://cloud.lsd.ufcg.edu.br:5000/v3
curl -o /dev/null -w '%{http_code}' https://cloud.lsd.ufcg.edu.br:9876/
```

## O que aconteceu

O nome resolve para **150.165.85.2** (`cloud6.lsd.ufcg.edu.br`). Os três
serviços responderam:

| Serviço | Porta | Resposta |
| --- | --- | --- |
| Dashboard (Horizon) | 443 | HTTP 302 (redireciona para o login) |
| Keystone | 5000 | HTTP 200 |
| Octavia | 9876 | HTTP 200 |

O `302` do dashboard é o comportamento normal: a raiz redireciona para
`/auth/login/`. O `200` do Keystone indica que a API de identidade está no ar.
A latência de ~0,3 s é a da rede do host até a UFCG.

## Decisões

- Usar `https://cloud.lsd.ufcg.edu.br:5000/v3` como `OS_AUTH_URL`, e não o
  `cloud5` que aparece no `openrc.sh` antigo da imagem (ver T0.3).
