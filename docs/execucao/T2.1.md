## Objetivo

Criar o par de chaves que a VM vai aceitar no SSH e que eu vou usar para chegar
nela pelo balanceador. Sem chave, a imagem `ubuntu-24.04` não permite login.

## Comandos executados

```bash
umask 077
ssh-keygen -t rsa -b 2048 -N '' -f ~/.ssh/atividade3-daniel-ranya
openstack keypair create --public-key ~/.ssh/atividade3-daniel-ranya.pub atividade3-daniel-ranya
openstack keypair list
ssh-keygen -lf ~/.ssh/atividade3-daniel-ranya.pub
```

## O que aconteceu

A chave privada foi gerada na VDI com permissão `600` (por causa do `umask 077`)
e a pública foi registrada na nuvem com o nome `atividade3-daniel-ranya`. O
`keypair list` confirma a impressão digital
`6e:e2:95:41:44:63:22:5f:32:c6:18:0d:e8:c8:db:58`.

Só a chave **pública** vai para a nuvem e só o par de chaves local fica na VDI. A
chave privada nunca é copiada para o repositório — o `.gitignore` bloqueia
`*.pem` e `*.key`, e nenhum arquivo de chave foi adicionado ao projeto.

O tipo RSA 2048 foi escolhido por ser o que a imagem Ubuntu aceita sem ajuste de
`sshd_config`; chaves ED25519 também funcionariam, mas exigiriam verificar a
negociação com o servidor.

## Decisões

- Nome com sufixo do grupo (`atividade3-daniel-ranya`) para não conflitar com as
  chaves dos outros grupos no mesmo projeto.
- Gerar a chave dentro da VDI, não no Windows: é de lá que o SSH é feito.
