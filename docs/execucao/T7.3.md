# T7.3 — Prova de que o log está no volume

**Data (UTC):** 2026-10-29T05:11:49Z
**Fase:** 7 — logs no volume e rotação
**Status:** concluída
**Evidências:** `evidencias/T7.3-log-in-volume.txt` · `T7.3-log-in-volume.png` · `T7.3-health.*`

## Objetivo

Mostrar, com um comando do sistema de arquivos, que o arquivo de log **reside no
volume** e não no disco raiz. "Configurar" não é prova; `stat -c %m` é.

## Comandos executados

```bash
ssh ... 'sudo ls -l /mnt/atividade3-logs/{cpu,memory,io}
    for f in /mnt/atividade3-logs/*/app.log; do
        printf "%s -> montado em %s\n" "$f" "$(sudo stat -c %m $f)"; done
    sudo tail -n 2 /mnt/atividade3-logs/cpu/app.log
    df -h /mnt/atividade3-logs'
```

## O que aconteceu

O `stat -c %m` devolve o **ponto de montagem** do sistema de arquivos onde o
arquivo está — é a resposta direta à pergunta "isto está no volume?":

```text
/mnt/atividade3-logs/cpu/app.log    -> montado em /mnt/atividade3-logs
/mnt/atividade3-logs/memory/app.log -> montado em /mnt/atividade3-logs
/mnt/atividade3-logs/io/app.log     -> montado em /mnt/atividade3-logs
```

Se os drop-ins não tivessem funcionado, os arquivos estariam em `/` e o valor
seria `/`.

O conteúdo confirma que são os processos novos, não os antigos: o `cpu/app.log`
tem 140 bytes e timestamp de 04:17 — o instante do `restart` do T8.4, quando o
`app-cpu` voltou. Os três arquivos `app.log.1` são os restos da rotação forçada
do T7.4, e o `app.log` de memory e io está em 0 byte porque o serviço só escreve
na inicialização.

O `df` fecha a prova: o volume tem 974 MB, 60 KB em uso.

O `a3-smoke` na mesma fase confirma que a mudança de destino não quebrou o
serviço: os três perfis continuam respondendo `200` em `/health` e `/work`.

## Saída

```text
/mnt/atividade3-logs/cpu:
total 8
-rw-r--r-- 1 root root 140 Oct 29 04:17 app.log
-rw-r--r-- 1 root root 140 Oct 29 03:50 app.log.1

/mnt/atividade3-logs/cpu/app.log -> montado em /mnt/atividade3-logs
/mnt/atividade3-logs/memory/app.log -> montado em /mnt/atividade3-logs
/mnt/atividade3-logs/io/app.log -> montado em /mnt/atividade3-logs

Filesystem      Size  Used Avail Use% Mounted on
/dev/vdb        974M   60K  948M   1% /mnt/atividade3-logs
```

## Decisões

- Usar `stat -c %m` em vez de só listar o diretório: listar prova que o arquivo
  existe no caminho, não que o caminho está montado.
- Manter os `.1` da rotação na captura: eles mostram que a rotação do T7.4 já
  tinha rodado no volume.

## Problemas e pendências

A primeira captura desta evidência rodou `stat` como `ubuntu`, que não tem
permissão de leitura no diretório `0750 appsvc`, e a saída saiu com três
`Permission denied` seguidos de linha vazia. A captura foi refeita com
`sudo stat`, e o resultado é o que está acima.
