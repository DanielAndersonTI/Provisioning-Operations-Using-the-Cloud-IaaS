# T1.6 — Portas do projeto na rede da VIP

**Data (UTC):** 2026-10-29T03:06:37Z
**Fase:** 1 — reconhecimento
**Status:** concluída
**Evidências:** `evidencias/T1.6-port-list.txt` · `T1.6-port-list.png`

## Objetivo

Localizar a porta de rede que materializa a VIP do balanceador e confirmar o
endereço IP flutuante associado a ela. Esse é o endereço pelo qual o mundo
externo alcança as VMs, já que elas não têm IP público.

## Comandos executados

```bash
openstack port list --server poi-atividades
openstack port list -c ID -c 'Fixed IP Addresses' -c 'Floating IP Addresses' -c Status \
  | grep -E '10\.5\.8\.242|150\.165\.85\.77'
```

## O que aconteceu

A porta `7351e4d4-ba2c-4922-a582-e63d3c00410e` carrega o endereço fixo
`10.5.8.242` na sub-rede `provider-sub` — é a VIP do balanceador. Ela aparece como
`DOWN` porque o Octavia mantém a porta da VIP em estado desativado do ponto de
vista do Neutron; o tráfego é atendido pelo amphora, não por essa porta
diretamente.

O endereço público correspondente é `150.165.85.77`, citado pelo professor na
conversa reproduzida no enunciado ("vocês devem configurar o lb para acessar a
vm via o ip público dele"). Essa é a única entrada externa para a minha VM.

## Saída

```text
| 7351e4d4-ba2c-4922-a582-e63d3c00410e | ip_address='10.5.8.242', subnet_id='17de9c72-...' |  | DOWN |
```

## Decisões

- Usar sempre `150.165.85.77:<porta>` nos testes externos.
- Não pedir IP flutuante para a VM: o enunciado prevê o acesso pelo balanceador e
  a cota de IPs flutuantes é compartilhada.

## Problemas e pendências

Nenhum.
