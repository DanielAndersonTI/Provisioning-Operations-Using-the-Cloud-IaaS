# T9.2 — Criação do snapshot

**Data (UTC):** 2026-10-29T05:12:45Z
**Fase:** 9 — snapshot da VM configurada
**Status:** concluída
**Evidências:** `evidencias/T9.2-snapshot-create.txt` · `T9.2-snapshot-create.png`

## Objetivo

Tirar o snapshot da VM já configurada, como o item 6 da segunda parte da
atividade pede, e esperar a imagem sair de `queued` antes de seguir.

## Comandos executados

```bash
openstack server image create --name snap-vm-daniel-ranya vm-daniel-ranya
# espera a imagem sair de queued/saving
openstack image show snap-vm-daniel-ranya -c status -f value
```

## O que aconteceu

O comando cria uma **imagem** do Glance a partir do disco da instância, e não um
snapshot de volume do Cinder: o `image_type` da imagem nova já vem
`snapshot` e o `instance_uuid` aponta para a `vm-daniel-ranya`.

| Campo | Valor no retorno |
| --- | --- |
| id | `7fb6d24c-583d-4f04-b843-5a1a35424816` |
| name | `snap-vm-daniel-ranya` |
| status inicial | `queued` |
| `instance_uuid` | `bdc0447e-fb71-48c8-9ce2-04a8c5e20ee0` |
| `base_image_ref` | `8ac7c385-...` (`ubuntu-24.04`) |
| visibility | `private` |

O `base_image_ref` prova que o snapshot descende da imagem exigida pela
atividade. A visibilidade fica `private`, que é o esperado dentro do projeto.

## Saída

```text
+------------+--------------------------------------------------+
| Field      | Value                                            |
+------------+--------------------------------------------------+
| id         | 7fb6d24c-583d-4f04-b843-5a1a35424816             |
| name       | snap-vm-daniel-ranya                             |
| status     | queued                                           |
| properties | image_type='snapshot',                           |
|            | instance_uuid='bdc0447e-fb71-48c8-9ce2-04a8c...' |
| visibility | private                                          |
+------------+--------------------------------------------------+
```

## Decisões

- Nome com o mesmo sufixo da VM (`daniel-ranya`) para deixar óbvio a quem o
  snapshot pertence, já que a lista de imagens é compartilhada com a turma.
- Um `python` externo esperou o status virar `active` antes do registro da T9.3:
  `openstack server image create` retorna enquanto a imagem ainda está `queued`,
  e conferir antes disso só mostraria o estado intermediário.
- O snapshot foi tirado com o volume anexado. O snapshot da instância captura o
  disco do sistema; o volume fica fora dele, o que a T9.3 confere em seguida.

## Problemas e pendências

Nenhum. A imagem passou de `queued` para `active` em cerca de 2 minutos.
