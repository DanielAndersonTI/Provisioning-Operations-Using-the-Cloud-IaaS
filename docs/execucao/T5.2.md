## Objetivo

Levar o código da Atividade 2 da VDI para dentro da VM sem expor a VM e sem
depender de `scp` porta a porta — o único caminho é o SSH pela VIP.

## Comandos executados

```bash
tar czf - -C ~/atividade3 apps | ssh ... ubuntu@150.165.85.77 'sudo tar xzf - -C /opt/atividade3'
ssh ... ubuntu@150.165.85.77 'find /opt/atividade3/apps -type f | sort; du -sh /opt/atividade3/apps'
sha256sum apps/server.py apps/{cpu,memory,io}/server.py
ssh ... ubuntu@150.165.85.77 'sha256sum /opt/atividade3/apps/server.py /opt/atividade3/apps/{cpu,memory,io}/server.py'
```

## O que aconteceu

O código foi empacotado em um `tar.gz` **no stream**: o `tar` lê da VDI e escreve
na saída padrão, que é o `stdin` do `ssh`, e do outro lado o `tar` extrai direto
em `/opt/atividade3`. Nada é gravado em disco intermediário e não é necessário
abrir uma segunda porta.

Chegaram quatro arquivos, 40 KB no total:

| Arquivo | Papel |
| --- | --- |
| `apps/server.py` | servidor genérico, recebe `--port` e o perfil |
| `apps/cpu/server.py` | perfil cpu, trabalho intensivo de FP/sha256 |
| `apps/memory/server.py` | perfil memory, aloca e verifica blocos |
| `apps/io/server.py` | perfil io, escreve e relê arquivos |

Os `sha256sum` calculados na VDI e na VM são **idênticos** para os quatro
arquivos — a transferência foi feita byte a byte:

```text
bc5e5b1c42a8b53b8907009bc5d1ed9f32ed84bcff628d5a7ea97ceaae83042c  apps/server.py
a1cf580a6e296c4802c1d8829946eba70469d9e3df33f760e7a55dd1ac9e689e  apps/cpu/server.py
3d0904c7b777dc1a98998716be284036dae1326c5e42541d2da69930600af0f8  apps/memory/server.py
20a2e5d3dd0fe85933683eadce189ae13722c5df7e1d3fab10d5ee1e991df217  apps/io/server.py
```

## Saída

```text
/opt/atividade3/apps/cpu/server.py
/opt/atividade3/apps/io/server.py
/opt/atividade3/apps/memory/server.py
/opt/atividade3/apps/server.py
40K	/opt/atividade3/apps
```

## Decisões

- `tar` pelo `stdin` do SSH em vez de `scp -r`: uma conexão, um comando, e o
  destino é descompactado com `sudo` sem precisar dar permissão de escrita em
  `/opt` a ninguém.
- Conferir o `sha256` dos dois lados: sem isso, um arquivo truncado só apareceria
  como erro de sintaxe na hora de subir o serviço.
