# T1.3 — Checagem do flavor e do balanceador

## Objetivo

Confirmar os dois recursos que o enunciado nomeia de forma explícita — o flavor
`general.small` e o balanceador `poi-atividades` — antes de usá-los. Vale a pena
porque um nome errado em um desses dois campos faz a criação da VM falhar
depois de vários minutos.

## Comandos executados

```bash
openstack flavor show general.small
openstack flavor list -f value -c Name
openstack loadbalancer show poi-atividades
```

## O que aconteceu

O flavor existe e tem **1 vCPU, 2048 MB de RAM, 20 GB de disco e swap igual a
zero**. O campo `properties` mostra
`aggregate_instance_extra_specs:type='general'`, o que explica o prefixo comum
dos nomes: o scheduler coloca essas VMs em um conjunto de hosts dedicado.

O `flavor list` mostra que todos os flavors do projeto começam com `general.`;
não há um flavor de mesmo tamanho com outro nome.

O comando do balanceador **falhou** com
`'loadbalancer show poi-atividades' is not an openstack command`. Não era erro de
nome nem de permissão: o cliente `python-openstackclient` 5.8.0 não traz os
comandos do Octavia, que vivem em um plugin separado. A correção está em T1.4.

## Saída

```text
| disk     | 20    |
| name     | general.small |
| properties | aggregate_instance_extra_specs:type='general' |
| ram      | 2048  |
| swap     |       |
| vcpus    | 1     |
```

```text
openstack: 'loadbalancer show poi-atividades' is not an openstack command.
```

## Decisões

- Manter `general.small` (1 vCPU) como cenário único: a atividade pede uma VM
  por grupo, e o interesse do experimento é medir o comportamento das três
  aplicações nessa máquina pequena.

## Problemas e pendências

O comando do balanceador só passa a funcionar após instalar o plugin (T1.4).
