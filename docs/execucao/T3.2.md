## Objetivo

Criar a VM do grupo com o flavor, a imagem, a chave, a rede e o grupo de
segurança que o enunciado determina.

## Comandos executados

```bash
openstack server create \
  --flavor general.small \
  --image ubuntu-24.04 \
  --key-name atividade3-daniel-ranya \
  --network provider \
  --security-group sg-daniel-ranya \
  vm-daniel-ranya --wait
openstack server show vm-daniel-ranya -f value -c addresses
openstack server list
```

## O que aconteceu

A VM `vm-daniel-ranya` (`bdc0447e-fb71-48c8-9ce2-04a8c5e20ee0`) foi criada e
ficou `ACTIVE` em cerca de 10 segundos, na zona `nova`, com
`provider=10.5.9.15`.

O endereço é **privado**. Não há IP flutuante associado — e nem haveria: o
enunciado prevê o acesso externo pelo balanceador. Confirmando com o que foi
visto em T1.1, nenhuma VM do projeto tem IP público.

Um detalhe de segurança: a saída do `server create` traz um campo `adminPass`,
uma senha inicial gerada pela nuvem. Em imagens Ubuntu de nuvem o login por senha
fica desabilitado (`PasswordAuthentication no`), então essa senha não dá acesso a
nada; ainda assim, ela foi removida das evidências publicadas, porque não é
informação útil para o relatório e não deve ficar em repositório.

## Decisões

- Criar a VM já com o grupo de segurança próprio: criar primeiro e ajustar
  depois exigiria `add security group` e uma janela em que a VM estaria exposta
  ao grupo `default`.
- Não associar IP flutuante.
