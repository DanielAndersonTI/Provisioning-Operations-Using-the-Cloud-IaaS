**Data (UTC):** 2026-10-29T02:29Z – 02:45Z

## Objetivo

Obter um token do Keystone e confirmar que a conta do grupo acessa o projeto
`provisionamento`.

## Comandos executados

```bash
openstack token issue        # com OS_* montadas por cloud_login.sh
```

Também foi testado `https://cloud.lsd.ufcg.edu.br/identity/v3`, que não expõe
descoberta de versões.

## O que aconteceu

Todas as tentativas devolveram **HTTP 401 (autenticação requerida)**. Como até a
autenticação **sem escopo de projeto** falha, o problema não é permissão no
projeto `provisionamento`: o par usuário/senha (ou o domínio) está sendo
rejeitado pelo Keystone.

Duas hipóteses ficam de pé:

1. O nome de usuário correto é o da **planilha** do professor, que pode não ser
   `daniel.silva` — o enunciado diz que contas novas usam "o username da
   planilha em anexo".
2. A senha informada (omitida aqui de propósito) difere da cadastrada, ou o domínio do
   usuário não é nem `Default` nem `Geral`.

As tentativas foram interrompidas de propósito, para não arriscar bloqueio da
conta por excesso de falhas.

## O que falta

- Confirmar no dashboard (`https://cloud.lsd.ufcg.edu.br`) qual é o login e se
  ele entra com a senha informada.
- Se entrar, baixar **Projeto → Acesso à API → OpenStack RC V3** e informar
  apenas as linhas `OS_AUTH_URL`, `OS_USER_DOMAIN_NAME`, `OS_PROJECT_DOMAIN_NAME`,
  `OS_PROJECT_NAME` e `OS_USERNAME` (a senha não precisa ser enviada de novo).

## Impacto

Nenhuma entidade foi criada na nuvem até aqui. Tudo o que depende do Keystone
(Fases 1 a 9) fica parado até a autenticação funcionar.
