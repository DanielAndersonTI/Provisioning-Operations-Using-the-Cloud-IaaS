# T7.1 — Diretórios de log no volume

**Data (UTC):** 2026-10-29T03:50:22Z
**Fase:** 7 — logs no volume e rotação
**Status:** concluída
**Evidências:** `evidencias/T7.1-volume-dirs.txt` · `T7.1-volume-dirs.png`

## Objetivo

Preparar, dentro do volume, os três diretórios que vão receber os logs, com o
dono correto para o usuário que roda os serviços.

## Comandos executados

```bash
ssh ... 'sudo install -d -o appsvc -g appsvc -m 0750 \
      /mnt/atividade3-logs/cpu /mnt/atividade3-logs/memory /mnt/atividade3-logs/io
    ls -ld /mnt/atividade3-logs{,/cpu,/memory,/io}
    findmnt -no SOURCE,TARGET,FSTYPE /mnt/atividade3-logs'
```

## O que aconteceu

| Caminho | Dono | Permissão |
| --- | --- | --- |
| `/mnt/atividade3-logs` | root | 0755 |
| `/mnt/atividade3-logs/cpu` | appsvc | 0750 |
| `/mnt/atividade3-logs/memory` | appsvc | 0750 |
| `/mnt/atividade3-logs/io` | appsvc | 0750 |

A raiz do volume continua de `root` e o `lost+found` também; só as pastas de log
pertencem ao serviço. Assim o `appsvc` não pode criar arquivos na raiz do volume,
apenas dentro do próprio perfil.

A verificação `findmnt` foi incluída na mesma captura de propósito: ela mostra
que os diretórios estão sendo criados **no volume** (`/dev/vdb`), e não no disco
raiz caso a montagem tivesse falhado.

## Saída

```text
drwxr-xr-x 6 root   root   4096 Oct 29 03:49 /mnt/atividade3-logs
drwxr-x--- 2 appsvc appsvc 4096 Oct 29 03:49 /mnt/atividade3-logs/cpu
drwxr-x--- 2 appsvc appsvc 4096 Oct 29 03:49 /mnt/atividade3-logs/io
drwxr-x--- 2 appsvc appsvc 4096 Oct 29 03:49 /mnt/atividade3-logs/memory

/dev/vdb /mnt/atividade3-logs ext4
```

## Decisões

- Um diretório por perfil, espelhando `/var/log/atividade3`.
- `0750 appsvc`: o `systemd` abre o arquivo como root antes de baixar privilégio,
  então a permissão estreita não impede a escrita.

## Problemas e pendências

Nenhum.
