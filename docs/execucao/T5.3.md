## Objetivo

Transformar os quatro arquivos Python em três serviços de verdade: com
reinício automático, início no boot e log próprio por perfil.

## Comandos executados

```bash
tar czf - -C ~/atividade3/payload/units . | ssh ... ubuntu@150.165.85.77 \
    'sudo tar xzf - -C /etc/systemd/system; sudo chmod 0644 /etc/systemd/system/app-*.service'
ssh ... ubuntu@150.165.85.77 'systemctl cat app-cpu app-memory app-io'
cat ~/atividade3/payload/a3-smoke | ssh ... ubuntu@150.165.85.77 \
    'sudo tee /usr/local/bin/a3-smoke >/dev/null; sudo chmod 0755 /usr/local/bin/a3-smoke'
```

## O que aconteceu

Foram instaladas três units (`app-cpu`, `app-memory`, `app-io`) com o mesmo
desenho, mudando apenas perfil, porta e arquivo de log:

```ini
[Unit]
Description=Atividade 3 - aplicacao cpu (porta 8000)
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=appsvc
Group=appsvc
WorkingDirectory=/opt/atividade3/apps
Environment=PYTHONUNBUFFERED=1
ExecStart=/usr/bin/python3 /opt/atividade3/apps/cpu/server.py --port 8000
Restart=on-failure
RestartSec=2
TimeoutStopSec=5
StandardOutput=append:/var/log/atividade3/cpu/app.log
StandardError=append:/var/log/atividade3/cpu/app.log

NoNewPrivileges=yes
PrivateTmp=yes
ProtectHome=yes
ProtectSystem=full
ReadWritePaths=/var/log/atividade3/cpu

[Install]
WantedBy=multi-user.target
```

Cada diretiva foi escolhida por um motivo:

| Diretiva | Motivo |
| --- | --- |
| `User=appsvc` | o serviço não roda como root |
| `Restart=on-failure` + `RestartSec=2` | se o processo morrer, volta sozinho em 2 s |
| `Environment=PYTHONUNBUFFERED=1` | sem isso o log só apareceria quando o buffer enchesse, e a medição por linha ficaria inútil |
| `StandardOutput=append:` | o `systemd` escreve direto no arquivo, sem passar pelo journal; é o que permite o log ficar no volume (fase 7) |
| `NoNewPrivileges`, `ProtectHome`, `ProtectSystem=full` | o processo não consegue escalar privilégio nem escrever em `/opt` e `/home` |
| `PrivateTmp=yes` | `/tmp` privado por serviço |
| `ReadWritePaths=/var/log/...` | única exceção de escrita, e limitada ao diretório do próprio perfil |

Também foi instalado o `/usr/local/bin/a3-smoke`, um script que testa os três
perfis de uma vez (porta, `/health`, `/work` e tempo de resposta) e aceita
`A3_HOST`/`A3_CPU_PORT`/`A3_MEMORY_PORT`/`A3_IO_PORT` para ser usado tanto em
`127.0.0.1` quanto pela VIP.

## Decisões

- Uma unit por perfil, em vez de um único serviço com três processos: assim cada
  perfil tem estado de saúde, log e reinício independentes — e o teste de
  falha do balanceador (T8.4) pode parar **um** perfil sem derrubar os outros.
- O `a3-smoke` ficou na VM e é chamado pela VIP a partir dela mesma; a VDI não
  tem esse script.
